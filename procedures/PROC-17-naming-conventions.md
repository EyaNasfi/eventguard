# PROC-17 — Naming conventions

## Purpose
Keep names consistent so that people and search tools find records easily.

## Who can do this
Everyone who creates or updates records: **editors** and **admins**.

## Steps
1. **Editions:** "Rendez-vous YYYY", for example "Rendez-vous 2027". The year in the name equals the edition year.
2. **Events:** the theme name without the year, for example "People Forum". The edition carries the year, so a copy keeps the same name.
3. **Event types:** use the type field (`conference`, `club`, `evening`), not the name, to say what kind of event it is.
4. **Sessions:** a short title in sentence case, without the event name.
5. **Speakers:** first name and last name in their own fields; the company goes in `company`, not in the name.
6. **Partners:** the organisation's usual name, with no legal suffix unless one is needed to tell two apart.
7. **Venues and rooms:** the same spelling every time; check existing events first.

## Checks before and after
- **Before:** search for an existing record with the same name to avoid duplicates.
- **After:** the new name follows the rule for its type.

## Common mistakes
- Adding "2027" to a copied event's name.
- Putting "(copy)" in names.
- Two spellings of the same venue.
